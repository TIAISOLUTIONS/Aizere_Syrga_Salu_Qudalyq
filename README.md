# Айзере · Сырға салу & Құдалық той

Полностью написанный вручную адаптивный сайт. Не Tilda, не конструктор. HTML + CSS + JavaScript, без сборки и обязательных зависимостей. Шрифты локальные, кириллица и казахские буквы поддерживаются. Гостевой интерфейс целиком на казахском. Для запуска нужен обычный статический хостинг, а для ответов — ваш проект Supabase.

## Сначала главное

**Сайт уже можно открыть. Реальная отправка ответов включится только после настройки Supabase ниже.** До подключения форма явно сообщает, что приём не подключён, и не показывает ложный успех. В архиве нет чужих ключей, готовой облачной базы или придуманного URL опубликованного сайта. Аккаунты GitHub, Supabase и Vercel создаёте вы; доступ к вашим аккаунтам мне не нужен. Интерфейсы сервисов могут немного меняться.

## Шаг 1. Создайте базу Supabase

1. Откройте https://supabase.com/ и создайте аккаунт.
2. В Dashboard нажмите **New project**. Выберите организацию, назовите проект `aizere-invitation`, придумайте надёжный пароль БД. Выберите доступный подходящий регион. Пароль БД никому не передавайте.
3. Дождитесь готовности проекта.
4. Откройте **SQL Editor → New query**.
5. На компьютере откройте `supabase/schema.sql` обычным текстовым редактором. Скопируйте **весь** файл в SQL Editor и нажмите **Run**. Выполняйте только в отдельном новом проекте либо предварительно проверьте отсутствие одноимённых объектов.
6. В **Table Editor** появится `guest_responses`. Пока она пустая — это нормально.
7. В настройках проекта найдите **Project URL** (обычно Settings → Data API / API) и **Publishable key** (Settings → API Keys). В новых проектах ключ начинается с `sb_publishable_`. Legacy `anon` тоже поддерживается. Базовая интеграция использует стандартный домен `https://….supabase.co`.

## Шаг 2. Подключите сайт — только два значения

Откройте `config.js` и заполните:

```js
window.INVITATION_CONFIG = Object.freeze({
  supabaseUrl: "https://ВАШ_PROJECT_REF.supabase.co",
  supabasePublishableKey: "sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ"
});
```

Сохраните файл. Кавычки должны остаться. Не добавляйте `/rest/v1` к URL.

**Никогда не вставляйте `service_role`, `sb_secret_`, пароль базы или персональные токены.** `config.js` будет общедоступен — и это ожидаемо для publishable/anon ключа. Безопасность обеспечивается правами и RLS в SQL, а не секретностью публичного ключа. Сайт дополнительно блокирует известный формат secret/service_role ключей, но это не заменяет внимательность. Если случайно опубликовали секрет — немедленно отзовите/замените его в Supabase, удаления файла из репозитория недостаточно.

Обычные Vercel Environment Variables сами по себе **не изменяют** этот статический `config.js`; заполните файл непосредственно. Сборка не требуется.

## Шаг 3А. Публикация в GitHub Pages — самый простой вариант

1. Распакуйте ZIP.
2. На https://github.com/new создайте репозиторий, например `aizere-invitation`. Для простого бесплатного Pages обычно используют публичный репозиторий; доступность приватного зависит от плана.
3. Загрузите **содержимое папки проекта**, а не сам ZIP и не лишнюю внешнюю папку. Файл `index.html` должен лежать в корне репозитория рядом с `styles.css`, `app.js`, `config.js` и папкой `assets`.
4. Убедитесь, что `assets/fonts` и файлы `.woff2` загружены. Если интерфейс не показывает `.nojekyll`, включите показ скрытых файлов или добавьте этот пустой файл отдельно. GitHub принимает папки перетаскиванием в окно Upload files.
5. Нажмите **Commit changes**.
6. Откройте **Settings → Pages → Build and deployment**.
7. Source: **Deploy from a branch**; Branch: **main**, Folder: **/(root)**; нажмите **Save**.
8. Дождитесь успешной публикации. Адрес будет примерно `https://ВАШ_ЛОГИН.github.io/aizere-invitation/` — используйте фактический адрес из Pages, не этот пример.
9. Откройте ссылку на телефоне. Проверьте отправку и таблицу (шаг 4).

Все пути в коде относительные (`./…`), поэтому сайт работает и в подпапке GitHub Pages. GitHub Pages не запускает серверный код, но он здесь не нужен: форма безопасно обращается к Supabase по HTTPS из браузера.

## Шаг 3Б. Альтернатива: Vercel

1. Сначала загрузите проект на GitHub, как в пунктах 1–5 выше.
2. В https://vercel.com/ войдите через GitHub.
3. **Add New → Project → Import** нужного репозитория.
4. **Framework Preset: Other**. **Root Directory** — папка с `index.html` (обычно корень).
5. **Build Command**: не нужен (пусто / override выключен). **Output Directory**: `.`. **Install Command**: можно оставить пустым (override, если требуется) — зависимости для сайта не нужны.
6. Нажмите **Deploy**. Файл `vercel.json` уже задаёт статическую публикацию без сборки.
7. Откройте выданный Vercel адрес и пройдите шаг 4. Следующие коммиты будут обновлять сайт автоматически при настроенной Git-интеграции.

## Шаг 4. Проверьте РЕАЛЬНУЮ отправку до рассылки

1. Откройте свой опубликованный сайт по HTTPS. Не должно быть предупреждения «Жауап қабылдау әлі қосылмаған».
2. Введите тестовое имя, выберите «өзім келемін», поставьте согласие и отправьте.
3. Успех показывается **только** при подтверждённом ответе базы с ID заявки.
4. Откройте Supabase → Table Editor → `guest_responses`, обновите данные. Должна появиться строка с `guest_count = 1`.
5. Перезагрузите сайт и проверьте пару (`couple`, два имени, `guest_count = 2`) и отказ (`declined`, `guest_count = 0`).
6. Удалите тестовые строки в Table Editor до рассылки гостям.
7. В SQL Editor выполните проверку прав из `supabase/admin-queries.sql`: `anon_select_must_be_false = false`, `anon_insert_must_be_false = false`, `rpc_must_be_true = true`.
8. Проверьте на настоящем iPhone/Android, в том числе во встроенном браузере мессенджера: открытие, прокрутка, выбор пары, клавиатура и отправка.
9. Откройте карту и убедитесь, что метка относится к вашему ресторану. По предоставленной ссылке 2GIS объект называется Quanysh; пользовательский текст «Қуаныш Гранд Холл», «Суан» сохранён как вы указали. На карте может отображаться более короткое имя из каталога.

## Где смотреть ответы и как выгрузить таблицу

**Supabase → Table Editor → guest_responses.** Войти можно только в ваш аккаунт / с разрешённым доступом команды. Публичной страницы со списком гостей специально нет.

Колонки:
- `guest_name` — имя и фамилия гостя;
- `attendance` — `alone` / `couple` / `declined`;
- `companion_name` — имя и фамилия супруга/супруги;
- `guest_count` — 1 / 2 / 0, рассчитывается самой БД;
- `message` — пожелание;
- `created_at` — время записи; база хранит timestamptz, Dashboard может показывать UTC;
- `consent_at`, `consent_version` — отметка согласия;
- `id` — технический идентификатор, не имя.

Для русских/казахских заголовков и времени UTC+5 откройте `supabase/admin-queries.sql`, выполните первый SELECT в SQL Editor. В панели результата выберите **Export / Download CSV**, если доступно. Такой CSV можно импортировать в Excel или Google Sheets (UTF-8, разделитель запятая). Второй запрос считает общее число подтверждённых людей. Одна строка пары = два человека. «Нет» остаётся в таблице, но не увеличивает число гостей.

Если Excel плохо показывает казахские буквы, используйте **Данные → Из текста/CSV → UTF-8**, а не открытие двойным щелчком. Онлайн-таблица здесь сама Supabase; постоянная синхронизация с Google Sheets не требуется и не настроена.

## Что уже сделано для безопасности и честного поведения

- RLS включён, прямые права на чтение/изменение таблицы у `anon` и `authenticated` отозваны.
- Публична только ограниченная функция `submit_rsvp`: она проверяет длины, статус участия и согласие, не возвращает чужие ответы и не позволяет перезаписывать строки.
- `security definer` использует пустой `search_path` и полные имена таблиц.
- Один и тот же сетевой запрос с одним ID повторно не создаёт строку. Это защита от сетевого дубля в текущей открытой странице, **не** гарантия уникальности человека после перезагрузки или с другого устройства.
- Неполученное подтверждение/ошибка сети никогда не выдаются за успешную отправку. При таймауте ответ мог уже попасть в базу: повторите без изменения полей на той же странице, чтобы использовать тот же ID.
- Нет имён и пожеланий в localStorage/sessionStorage, нет публичного списка гостей, нет аналитики и рекламных трекеров. Для прямого обращения к Supabase браузер технически передаёт IP/заголовки сервису; 2GIS загружается как сторонний iframe.
- Honeypot от простых ботов есть, но это **не серверный антиспам**. Публичный RPC можно вызывать извне. Для камерного приглашения обычно достаточно закрытой рассылки ссылки; для публичной рекламной раздачи добавьте серверную проверку CAPTCHA и rate limit через Edge Function/сервер. Здесь их нет. Не публикуйте URL в открытых каталогах, следите за лимитами сервиса.
- Сайт не индексируется по собственной директиве `noindex`, но это не пароль и не гарантия приватности. Ссылка и публичный GitHub-репозиторий доступны любому, у кого есть доступ.
- Публичный ключ не даёт читать список, если выполнена поставляемая SQL-схема. Не добавляйте SELECT-политики для гостей, не отключайте RLS.
- После праздника удалите персональные данные в Dashboard, когда они больше не нужны. Политика на сайте не задаёт автоматическую очистку; отвечают организаторы. Для исправления/удаления гость обращается к той иелеріне напрямую.

## Локальный просмотр

Можно открыть `index.html` двойным щелчком для просмотра дизайна. Полноценно проверять форму и доступ к буферу обмена лучше через HTTPS хостинг или локальный HTTP-сервер.

Если установлен Node.js: `npm start` (первый запуск `serve` скачивается через npx). Откройте фактический Local URL из терминала. Никакой npm build не нужен.

## Если что-то не работает

**Кнопка неактивна:** проверьте два значения `config.js`, сохранение и публикацию последнего коммита. Очистите кеш / откройте в приватной вкладке. Поддерживается стандартный `*.supabase.co` URL, не адрес Dashboard.

**Ошибка отправки:** убедитесь, что SQL выполнен целиком, проект активен, Data API доступен, ключ от этого же проекта. В DevTools → Network проверьте запрос `/rest/v1/rpc/submit_rsvp`. 404 обычно означает, что функция не создана/не обновилась схема API; 401/403 — неправильный ключ или права. Если после создания функции API ещё не видит её, дождитесь обновления кеша; в SQL Editor можно выполнить `NOTIFY pgrst, 'reload schema';`.

**Supabase приостановил проект:** проверьте статус проекта/план в Dashboard и восстановите работу. Условия бесплатных планов меняются: https://supabase.com/pricing. Перед мероприятием и перед массовой отправкой ссылки обязательно протестируйте форму. Без активной БД сайт читается, но ответы не сохраняются.

**Карта пуста:** внешняя сеть/блокировщик/2GIS. Используйте прямую кнопку; проверьте iframe в обычном браузере без блокировщика. Не используйте скриншот вместо живой карты.

**Вид без красивых шрифтов:** проверьте, что папка `assets/fonts` загружена, регистр имён не менялся. Система всё равно покажет резервный шрифт; внешние Google Fonts при открытии сайта не нужны.

**В GitHub видна только папка, сайт 404:** перенесите index.html в корень, проверьте main и /(root) в Pages. Сам ZIP GitHub Pages не распаковывает.

## Где что менять

- `index.html` — все казахские тексты, имена, календарная сетка и адрес;
- `styles.css` — цвета в `:root`, отступы, адаптация;
- `app.js` — точная дата для отсчёта и логика формы;
- `assets/aizere-invitation.ics` — файл добавления даты в календарь;
- `config.js` — два публичных значения Supabase;
- `supabase/schema.sql` — БД и защищённый приём;
- `supabase/admin-queries.sql` — запросы для организаторов.

Если меняете дату, измените её **везде**: HTML, календарь, JavaScript, ICS и метаданные. Текущее 22.11.2026 — воскресенье. В ICS начало 07:00 UTC соответствует 12:00 UTC+5. Не меняйте только надпись, забыв отсчёт.

## Дизайн и технические детали

Тёплая бумага, спокойный оливковый цвет, деликатное золото, арочная обложка, крупная антиква, тонкие линии. Нет тяжёлых фотографий, autoplay-аудио, обязательной заставки, слайдеров или сторонних JS-библиотек. Все декоративные элементы сделаны CSS/SVG, сторонние изображения из примера не копировались. Анимации появляются при прокрутке и отключаются через `prefers-reduced-motion`. Без JavaScript текст, календарь, карта и адрес остаются видимыми, форма требует JS.

Шрифты: Noto Serif Display и Noto Sans, лицензия SIL Open Font License; файлы и лицензии лежат в assets/fonts. Шрифты включены локально. Код проекта можно изменять для вашего приглашения.

Мета-изображение для мессенджеров специально не выдумывается: после публикации при желании добавьте свою картинку и абсолютный публичный `og:image` URL. Сейчас превью передаёт название и описание, внешний вид карточки выбирает мессенджер.
