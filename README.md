# Айзере — минимальная версия, v2

HTML + CSS + JavaScript. Без Тильды, сборки и обязательных npm-зависимостей. Все тексты гостя на казахском. Шрифты локальные. Дата: 22.11.2026, 12:00 по Жаркенту (UTC+5).

## Как обновить уже работающий сайт

1. Ваш существующий `config.js` НЕ МЕНЯЙТЕ — его нет в архиве обновления. В нём уже должны быть правильные Project URL и публичный ключ.
2. Откройте Supabase → существующий проект → SQL Editor → New query. Скопируйте ВЕСЬ обновлённый `supabase/schema.sql` и нажмите Run. Он сохраняет старые строки и обновляет функцию под упрощённую форму без согласия и пожеланий. Согласие НЕ подставляется автоматически: новые записи имеют NULL в исторических колонках consent_at/consent_version. Не запускайте старую версию schema.sql после обновления.
3. Загрузите файлы из папки `ФАЙЛЫ-ДЛЯ-ЗАМЕНЫ` в корень существующего GitHub-репозитория, сохраняя вложенные папки. Подтвердите замену файлов и Commit changes. Не загружайте саму внешнюю папку `ФАЙЛЫ-ДЛЯ-ЗАМЕНЫ`.
4. Дождитесь публикации GitHub Pages / Vercel. Откройте сайт в приватной вкладке. CSS и JS имеют `?v=2` для обхода старого кеша.
5. Отправьте тестовый ответ, убедитесь, что он появился в Supabase → Table Editor → guest_responses. Проверьте одиночный ответ, пару с обязательным именем и отказ. Удалите тестовые записи.

Если до обновления была открыта старая страница, обновите её перед отправкой: старый шестипараметрический RPC заменён новым четырёхпараметрическим. Существующие ответы не удаляются. Исторические колонки message/consent остаются для старых данных, новая форма их не заполняет.

## Фото первого экрана

Фотографию вы выбираете сами. По умолчанию — тёплый кремовый фон без пустой рамки или сломанной картинки. Никакое случайное фото не скачивается и не подставляется.

Варианты композиции:
1. Золотые серьги на светлом шёлке — лаконичный тематический фон для сырға салу.
2. Крупный план рук и серёг во время обряда — тёплый семейный сюжет.
3. Портрет Айзере в светлом наряде — персональное приглашение.

Используйте своё фото или изображение, на использование которого у вас есть права. Рекомендую вертикальный кадр 4:5 или 3:4, от 1200×1600 px, JPEG, желательно до 1–1.5 МБ. Необязательно точное разрешение: object-fit:cover сохранит пропорции без растяжения и обрежет лишнее по краям.

Назовите файл `cover.jpg` (настоящий JPEG, не переименованный PNG) и загрузите его в существующую папку `assets` на GitHub. Путь должен быть **assets/cover.jpg**, регистр букв важен. Подтвердите Commit и дождитесь публикации. Сайт автоматически подхватит изображение. Светлая подложка над фото сохраняет читаемость коричневого заголовка. Лицо/серьги лучше не размещать за надписью в центре.

Позиция кадра меняется в начале styles.css: `--cover-position:50% 45%;` — первое число горизонталь, второе вертикаль. Например `50% 25%` показывает больше верхней части. Путь меняется одной строкой `COVER_PHOTO` в app.js, если хотите другое имя или .webp. Элементы сайта не сдвигаются после загрузки фото.

## Подключение с нуля

Для уже подключённого сайта этот раздел пропустите. Для нового проекта: выполните schema.sql в новом Supabase, вставьте Project URL и Publishable key в ваш config.js. Никогда не публикуйте secret/service_role ключ. Основной проект использует стандартный `https://….supabase.co` адрес. Права чтения/прямой записи anon отозваны, публична только ограниченная функция. RLS не отключать.

GitHub Pages: index.html в корне → Settings → Pages → main → /(root). Vercel: импорт существующего репозитория → Other → без Build Command → Output Directory «.». Остальные файлы исходного проекта и config.js сохраняются, архив обновления не является полным проектом.

## Что изменилось

Нет хедера, футера, плавающих кнопок, номеров секций, цитат, рекламных подводок, мелких декоративных подписей, добавления в календарь, пожеланий и согласия. Тёплая коричнево-кремовая палитра, настоящий курсив с поддержкой казахских букв. Только приглашение, дата с календарём, отсчёт, адрес с картой/копированием, короткая анкета и той иелері.

Карта — официальный iframe 2GIS, точная метка по исходной локации, без отдельного API-ключа. Карточка ресторана не раскрывается при первоначальной загрузке. В org дважды передан ID той же организации: текущий виджет открывает карточку автоматически только для одной записи; метки совпадают в одной точке, дополнительных адресов нет. При нажатии на метку 2GIS может открыть свою карточку. Это поведение стороннего виджета может измениться. На карте остаются названия объектов, стандартные ссылки и обязательная атрибуция 2GIS — это интерфейс сервиса, не дополнительные тексты сайта. Гарантировать отсутствие русского языка внутри чужого iframe нельзя. Карта не зависит от Supabase.

Без настоящего ответа БД сайт не показывает успех. Сетевой повтор в той же открытой странице с теми же полями сохраняет прежний ID; это не защита от повторов с других устройств. У новой формы нет checkbox согласия, и сервер не регистрирует фиктивное согласие. Это техническое изменение не является заключением о соблюдении законодательства о персональных данных: применимые требования организаторы проверяют самостоятельно.

Публичный RPC по-прежнему не является полноценным серверным антиспамом. Не публикуйте ссылку массово в открытых каталогах. Ответы доступны в Dashboard, публичного списка гостей нет. Анонимные посетители не могут читать, менять или удалять чужие ответы. После мероприятия удалите персональные данные, когда они больше не нужны.
